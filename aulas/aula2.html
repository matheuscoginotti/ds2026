Aula 02: Modelagem Conceitual e DER

Repositório DS 2026 • Professor: Matheus M. Coginotti

Antes de abrir o XAMPP ou digitar qualquer linha de código SQL, um desenvolvedor de sistemas precisa desenhar a estrutura lógica do problema. A fase de Modelagem Conceitual serve exatamente para isso: mapear o mundo real para o papel utilizando o Diagrama Entidade-Relacionamento (DER).

1. O que compõe um DER?

O Diagrama Entidade-Relacionamento é composto por três elementos fundamentais:

  • Entidades: Representam os "objetos" ou "conceitos" do mundo real sobre os quais queremos guardar informações (ex: Cliente, Produto, Pedido). No modelo conceitual, são representadas por retângulos.
  • Atributos: São as características ou propriedades que descrevem uma entidade (ex: O cliente tem nome, cpf, telefone). São representados por elogas/círculos conectados à entidade.
  • Relacionamentos: Representam a associação lógica existente entre duas ou mais entidades (ex: Um Cliente realiza um Pedido). São representados por losangos.

2. Entendendo a Cardinalidade

A cardinalidade define quantas vezes uma entidade pode se relacionar com outra. É o conceito mais importante na hora de desenhar conexões corretas no banco de dados:

1 para 1 (1:1)

Ocorre quando um registro de uma tabela está associado a exatamente um registro de outra tabela.
Exemplo: Um Funcionário possui um único Crachá de acesso, e um crachá pertence a um único funcionário.

1 para N (1:N)

Ocorre quando um registro de uma tabela pode se relacionar com vários registros de outra, mas o inverso é verdadeiro apenas para um. É o relacionamento mais comum nos sistemas!
Exemplo: Uma Categoria pode conter vários Produtos, mas um produto específico pertence a uma única categoria.

N para N (N:N)

Ocorre quando vários registros de uma tabela se relacionam com vários registros de outra tabela simultaneamente.
Exemplo: Um Aluno pode se matricular em várias Disciplinas, e uma disciplina possui vários alunos matriculados.

# REGRA DE OURO DA RELAÇÃO N para N (N:N)
O banco de dados relacional não consegue ligar tabelas N para N diretamente.
Sempre que identificarmos um relacionamento N para N no DER conceitual, obrigatoriamente precisaremos criar uma tabela associativa (intermediária) na próxima etapa de projeto!

Imagine que você foi contratado para criar o sistema de uma Locadora de Filmes:

  1. Identifique no papel pelo menos 3 Entidades principais para este cenário.
  2. Escolha uma das entidades e liste 3 atributos fundamentais para ela.
  3. Defina qual é a cardinalidade (1:1, 1:N ou N:N) entre a entidade Cliente e a entidade Filme ao realizar uma locação. Justifique sua resposta.
