Seja bem-vindo ao módulo de Banco de Dados do 2º DS! Antes de criarmos tabelas ou escrevermos comandos SQL complexos, precisamos entender o motivo fundamental pelo qual os sistemas modernos dependem de um SGBD e como tratamos a informação de forma estruturada.

1. O que é um SGBD e por que usá-lo?

Imagine guardar o cadastro de clientes, produtos e vendas de uma grande empresa dentro de planilhas de Excel soltas ou arquivos de texto. Conforme o volume de dados cresce, surgem problemas graves: duplicidade de informações, falhas de segurança, lentidão e risco de corrupção de dados.

Um SGBD (Sistema de Gerenciamento de Banco de Dados) — como o MySQL que rodaremos através do XAMPP — é o software especializado que atua como intermediário entre a aplicação (seu sistema) e o armazenamento físico dos dados, garantindo:

  • Integridade: Garantir que os dados inseridos sigam regras lógicas válidas.
  • Concorrência: Permitir que milhares de usuários acessem e modifiquem dados ao mesmo tempo sem travar a base.
  • Segurança: Controle de permissões e perfis de acesso aos dados sigilosos.

2. O Modelo Relacional: Tabelas, Linhas e Colunas

O modelo relacional organiza as informações em estruturas bidimensionais chamadas de tabelas (ou entidades). Na prática da programação:

  • Colunas (Atributos): Representam as características do que estamos guardando (ex: nome, idade, preco). Cada coluna possui um tipo de dado obrigatório (como INT para números inteiros ou VARCHAR para textos).
  • Linhas (Registros ou Tuplas): Representam uma ocorrência única e completa (ex: o cadastro de um produto específico com todas as suas características preenchidas).
